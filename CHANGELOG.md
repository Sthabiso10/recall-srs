# Changelog

Per-package changelogs are generated by [changesets](https://github.com/changesets/changesets)
and live in each package directory. This file covers the repository as a whole.

All packages share a version line while we're pre-1.0.

## 0.1.2

### Fixed — second review pass

- **The relearning ladder now works inside a session.** Sessions built their queue once at
  construction, so a lapsed card scheduled ten minutes out was never shown again — the ladder
  was inert in the only path that matters. Sessions now reclaim cards whose step comes due,
  stay open while one is pending, and `useStudySession` polls so it works even when the
  learner is idle.
- **`preview()` no longer lies.** It recomputed the FSRS interval directly and so ignored the
  relearning ladder, advertising "Again · 580m" while grading Again scheduled 10 minutes. It
  now runs the real scheduling path, and a test asserts the two agree for every grade.
- **Invalid FSRS config throws instead of silently mixing defaults.** A 17-weight FSRS-4.5
  array was accepted and quietly filled the two missing weights from FSRS-5 defaults,
  producing a scheduler that is neither algorithm. Weight count, finiteness,
  `desiredRetention` range, interval bounds and relearning steps are all validated at
  construction.
- **`createCard` rejects an empty question or answer**, where it previously produced a card
  that rendered as a blank study screen.
- **`computeDeckStats` uses the study day**, matching how the scheduler anchors due dates.
  `dueToday` disagreed with the scheduler around the rollover hour.

### Added — the FSRS weight optimiser

`@recall-srs/core/optimizer` fits the 19 FSRS parameters to one learner's review history.
This is the argument for FSRS over SM-2 — the defaults are a population average, and the same
nineteen numbers fitted to your learners describe how *they* forget.

- `optimizeFSRSWeights(logs, options)` — gradient descent on log loss, with a held-out
  validation set and a plain-language recommendation about whether to adopt the result.
- `evaluateWeights(sequences, config)` — log loss, calibration RMSE and accuracy for any
  weight set.
- `buildTrainingSequences`, `splitSequences` — review logs into training data, split by card
  so one card's history never straddles train and validation.
- `FSRS_WEIGHT_BOUNDS`, `clampWeights`, `normalizeWeights` — parameter ranges and the
  normalisation the optimiser works in.

Three things worth knowing:

- It **refuses below ~400 reviews**. Fitting 19 parameters to thin history produces weights
  that describe the past well and predict the future worse than the defaults. Getting
  "keep the defaults" back is a successful run.
- It **never returns a fit worse than its starting point** — steps that raise the loss are
  rejected and the step size halves.
- It is a **separate entry point**, so a study screen never ships the fitting code. The main
  bundle is unchanged at 5.8 kB.

### Added — second review pass

- Cards mid-relearning are queued ahead of ordinary reviews.
- `resumeStudySession()` — restore a sitting from a serialised snapshot, so a reload or a
  backgrounded mobile app doesn't discard forty cards of progress.
- `applyLoadBalance()` — apply the moves `computeLoadBalance` proposes.
- `session.reclaim()` and `awaitingRelearning` on `useStudySession`, plus a `relearningState`
  slot on `<StudyView>` so "one card comes back shortly" is distinguishable from "you're done".
- `examples/minimal` — the engine in ~50 lines of Node, runnable with one command.
- Bundle budgets via `pnpm size`, enforced in CI.

Review pass over the first release. Several of these are behaviour changes to scheduling;
read them before upgrading.

### Fixed — scheduling

- **SM-2 now refuses to run.** `createScheduler()` throws `NotImplementedError` at
  construction. The stub it shipped with in 0.1.0/0.1.1 returned values that type-checked but
  collapsed every card to a fixed one-day interval forever, with no error. If you were using
  it, switch to `createFSRSScheduler()`.
- **Lapsed cards can return within the session.** Intervals had a one-day floor, so a card you
  just failed vanished until the next day, removing relearning entirely. FSRS now schedules
  sub-day intervals, defaulting to a ten-minute minimum.
- **Due dates anchor to the study day.** A card graded at 23:40 came due at 23:40, making it
  invisible during a morning session. Intervals of a day or more now anchor to the start of the
  target study day, with a configurable `dayStartsAtHour` (default 04:00).
- **Grading a suspended card throws** instead of returning the card unchanged while still
  writing a review log — those phantom logs polluted every retention statistic.
- **`maximumIntervalDays` defaults to 365**, down from 3650. Ten years was reachable in four
  Easy grades, and an interval nobody lives to see is indistinguishable from "never again".
- **Interval fuzz accepts an injected RNG**, so fuzzed scheduling is deterministic in tests.

### Fixed — other

- `progress()` no longer reports 100% while cards remain in the queue when `requeueLapses` is
  on. It now counts distinct cards graded, not grade events.
- `onSessionComplete` fires exactly once per sitting instead of on every render after the
  last card.
- `useStudySession` memoises session state and previews. Previously every render allocated
  three arrays and ran the FSRS model six times, and returned fresh object identities that
  broke memoisation downstream.

### Added

- `scheduler.gradeRating(card, 1..4)` — grade with native FSRS ratings, skipping the lossy
  0-5 round trip.
- `scheduler.reconstructMemory(logs)` — rebuild FSRS memory state by replaying a card's
  history. This is the good way to migrate an SM-2 deck.
- `computeLoadBalance()` — proposes due-date shifts to flatten workload spikes.
  `computeForecast` showed you the 300-card Thursday; this does something about it.
- `applyLeechPolicy()` — tag or suspend cards that keep lapsing. `isLeech` existed but nothing
  acted on it.
- `computeRetentionCurve()` and `computeStreak()` are implemented (they were stubs).
- `DeckStats` gains `averageStability`, `averageDifficulty` and `matureReviewCount`.
  `retentionRate` is now measured over mature reviews only — young cards flattered it badly.
- `StorageAdapter.saveReviews()` optional batch write, for flushing an offline session.
- Keyboard shortcuts on `<RatingButtons>` (number keys), with input fields correctly ignored.
- Accessibility: `aria-live` on the card so revealing an answer is announced, accessible names
  on the progress bar, `role="status"` on the summary.
- Test coverage for `@recall-srs/adapter-localstorage`, which previously had none.

### Changed

- **FSRS is now the default scheduler** in `createStudySession()` and `<SRSProvider>`.
- `<SRSProvider>`'s `schedulerConfig` prop is now `fsrsConfig`.
- The shared `scheduler` singleton export is gone. Construct one explicitly.
